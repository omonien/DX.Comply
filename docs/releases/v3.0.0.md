## Highlights

- **Compliance tool.** DX.Comply is a compliance tool for Delphi projects. An SBOM and a CPE for the product are the building blocks it writes today. Further areas can follow. The SBOM content is unchanged in that role: it is still the component list from the build, and it still does not make a product compliant.

- **CPE for the product.** `product.cpe` in `.dxcomply.json`, or `--cpe`, is written on the CycloneDX root component and on the built program, after `copyright` and before `purl`. SPDX 2.3 adds an `externalRefs` entry with `referenceCategory` `SECURITY` and `referenceType` `cpe23Type` or `cpe22Type`. SPDX 3.0.1 keeps that identifier through the existing conversion. A value that is neither a CPE 2.3 formatted string nor a CPE 2.2 URI is a warning and is left out. A component-manifest `cpe` on a library row is unchanged (#196).

- **Find or request a name.** **Project > DX.Comply - SBOM > SBOM and CPE...** opens the SBOM header and a CPE tab. The CPE tab fills vendor, product and version from the project configuration. **Search** calls the NVD CPE API 2.0 and lists matching names with title and deprecation. **Apply selected CPE** saves the choice as `product.cpe`. Nothing is requested until you start the search. When no name fits, **Save dictionary and mail text** writes a CPE Dictionary 2.3 file and a mail text for cpe_dictionary@nist.gov next to the SBOM, with provenance comments for the supplier URL and the repository URL, and copies the mail text to the clipboard. The vendor and product strings are a proposal. NIST may normalize them. DX.Comply does not send the message.

- **Command line.** `dxcomply.exe --cpe-lookup` prints the same NVD matches for the configured vendor and product and does not write an SBOM. `dxcomply.exe --cpe-dictionary` writes the two files next to the SBOM after generation and does not call the NVD. The optional NVD API key is `--nvd-api-key`, then the environment variable `NVD_API_KEY`, then `HKCU\Software\Developer Experts\DX.Comply\NIST` value `ApiKey`. It is not read from `.dxcomply.json` and it is not printed. The log names only which source was used. SBOM generation stays local. The NVD is called only for a search you start.

## Test coverage

DUnitX covers CPE 2.3 and CPE 2.2 formatting, dictionary XML escaping and provenance comments, a recorded NVD CPE API 2.0 response, the API-key resolution order with the environment and the registry abstracted, and `product.cpe` on CycloneDX and SPDX. The suite is run on Win32 and Win64 with the product build. This note does not restate a count from a machine that did not compile the tests.
