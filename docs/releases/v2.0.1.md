## Highlights

- **SBOM for a library source release.** `--library` writes an SBOM for source you ship, such as a component set or a library on GitHub, instead of a build. The root component is a `library` with name, version, licence, supplier, and package URL (`--purl`, or derived from a GitHub `--repo-url`). Every shipped file from the `.dpk` contains clause, the `.dpr` uses entries with an `in` path, and `--source-dir` walks is one component with SHA-256 and SHA-512. The `.dpk` requires packages are listed, with `rtl`, `vcl`, and `fmx` as frameworks. CycloneDX compositions say which sets are complete. The CRA and BSI header warnings run as in build mode. See `docs/Library-SBOM.md` (#64).

## New options

| Option | Config file key | Purpose |
|---|---|---|
| `--library[=true\|false]` | `library` | Library mode |
| `--source-dir=<dir>` (repeatable) | `sourceDirs` | Source directory, walked recursively |
| `--purl=<purl>` | `product.purl` | Package URL of the root component |
| `--repo-url=<url>` | `product.repoUrl` | Repository URL. A GitHub URL gives the purl when `--purl` is empty |

`--project` is optional in library mode when a source directory is set. Build mode is unchanged.

## New components

| Unit | Purpose |
|---|---|
| `DX.Comply.LibrarySource` | Reads `.dpk` contains and requires, `.dpr` uses-in entries, and collects the files of a source release |

## Test coverage

TESTCOUNT DUnitX tests pass on Win32 and Win64 (up from 434 in v2.0.0). The new tests cover the package and program parsers, the GitHub purl, file collection on a fixture package, a library SBOM written by the engine, and the new CLI options.
