## Highlights

- **Size and hashes for DLLs the program loads.** DLLs found by the source scan (`external`, `LoadLibrary`, `GetModuleHandle`) used to be written with no size and no hash. DX.Comply now looks for the file at the full path given in code, then in the application output directory. When it finds the file there, it records `file:size`, SHA-256, and SHA-512, plus `net.developer-experts.dx-comply:locationSource`. A DLL found only in System32 or SysWOW64 gets its location and no hash, because the copy on the build machine does not describe the target system. Thanks to Alexander Jung for the request (#59, #68).
- **Third-party DLLs and packages carry their own version.** A DLL or `.bpl` next to the program, or a DLL resolved by the scan above, gets the version from its own version resource (FileVersion, else ProductVersion). A file without a version resource gets no version (#73).
- **Product version on the project's own files.** In build mode, the program, the `.dcp`, and the file the project builds carry the product version. The first 12 hex characters of the SHA-256 are no longer written as the file version, and file components no longer get a `file:` package URL. Build mode now matches library mode here (#72).
- **Product version from git.** `--version-from-git-tag` takes the newest tag reachable from the checked-out commit in the project folder and removes a leading `v`, so `v2.1.0` becomes `2.1.0`. `--version` wins when both are set. Without git, a work tree, or a tag, DX.Comply prints a warning and goes on (#71).

## Fixes

- **Stale GetIt paths removed by the installer.** After the GetIt package was uninstalled, Delphi could keep reporting H2675 for folders under `CatalogRepository\DXComply-*`. The installer now removes entries under a `DXComply-*` folder that no longer exists from the Delphi 13 `Search Path`, `Browsing Path`, and `Debug DCU Path` (HKCU, BDS 37.0, every platform), on install and on uninstall. Other entries are not touched. `docs/GetIt.md` describes the manual workaround. Thanks to Markus Humm for the report (#67, #70).

## New options

| Option | Purpose |
|---|---|
| `--version-from-git-tag` | Product version from the newest git tag of the project folder |

## Test coverage

481 DUnitX tests pass on Win32 and Win64 (up from 445 in v2.0.1). The new tests cover DLL lookup and hashing, the system directories per platform, the git tag version, and which build files get the product version or their own version.
