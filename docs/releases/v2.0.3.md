## Highlights

- **SBOM header data in the IDE.** The new menu entry **Project > DX.Comply - SBOM > SBOM Header Data...** edits the SBOM creator, supplier, supplier URL, licence, and product version for the active project. The dialog checks the values like the CLI does and saves them in the `.dxcomply.json` next to the `.dproj`, keeping all other keys. The IDE now reads these keys when it generates, so the IDE and `dxcomply --ci` produce the same header. When a generation reports missing header data, DX.Comply offers to open the dialog and to generate again after you save. Warnings in the IDE name the dialog instead of CLI flags (#79).
- **IDE environment variable overrides in the CLI.** Paths in the `.dproj` can use variables set in Tools > Options > Environment Variables, for example `<DCC_ExeOutput>$(MyProject_bin)</DCC_ExeOutput>`. The IDE applies these overrides only to its own process, so the CLI left them unresolved and did not find the MAP file and the EXE. The CLI now looks a variable up in the process environment first, then in the overrides of the detected Delphi version (`HKCU\Software\Embarcadero\BDS\<version>\Environment Variables`). A variable that uses another one is expanded too. A variable found in neither place is named in a warning. Thanks to Loris-F for the report (#80, #81).

## Fixes

- **A .dpr with a .dproj next to it.** When you pass a `.dpr` and a `.dproj` with the same name is in the same folder, DX.Comply now scans the `.dproj`, like Delphi does, and says so in an info message (#75, #76).
- **Faster MAP file reading.** The MAP file regexes are compiled once instead of once per line, which cut minutes from large map files. Thanks to Roland Bengtsson for the change (#77). Unit names from the MAP file are now deduplicated in linear time instead of quadratic time (#78).
- **README.** The Quick Start now names the real menu entry, **Project > DX.Comply - SBOM > Generate SBOM...**

## Test coverage

519 DUnitX tests pass on Win32 and Win64 (up from 481 in v2.0.2). The new tests cover the SBOM header data, the .dpr to .dproj switch, large MAP files, and the IDE environment variable overrides.
