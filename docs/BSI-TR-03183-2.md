# BSI TR-03183-2 fields

DX.Comply reads [BSI TR-03183-2](https://www.bsi.bund.de/SharedDocs/Downloads/EN/BSI/Publications/TechGuidelines/TR03183/BSI-TR-03183-2_v2_1_0.pdf?__blob=publicationFile&v=6), version 2.1.0, 20 August 2025. Section 4 of that edition requires CycloneDX 1.6 or later, or SPDX 3.0.1 or later. DX.Comply writes CycloneDX 1.5 (JSON and XML) and SPDX 2.3 JSON. The tables below say which required and additional fields that output carries, and which it does not.

This is not a certification. It is not a claim that a generated file meets TR-03183-2.

## What the technical guideline requires

SBOM level (Table 2):

| Field | What DX.Comply writes |
|---|---|
| Creator of the SBOM (email, or a URL when there is no email) | `metadata.manufacture` in CycloneDX 1.5. An email is `contact.email`. A URL is `manufacture.url`. SPDX 2.3 has no URL on a creator, so an email is `Person: <email> (<email>)` and a URL is `creationInfo.comment`. Written only when you set `--sbom-creator` or `sbomCreator`. |
| Timestamp | `metadata.timestamp` and SPDX `creationInfo.created`. UTC is used when the clock value is UTC. |

Each file component (Table 3):

| Field | What DX.Comply writes |
|---|---|
| Component creator (email or URL) | Not known for a scanned file. Omitted. A manifest library uses `vendor`. An email vendor is also `supplier.contact.email` (CycloneDX) and SPDX `originator` `Person: <email> (<email>)`. `vendor_url` is the URL. |
| Component name | File name for a scanned file. Product name for the primary component. Manifest `name` for a library. |
| Component version | Product version, or the manifest `version`. A scanned file keeps the first 12 hex characters of its SHA-256. The file modification time is not used. |
| Filename | `bsi:component:filename`, and SPDX `packageFileName`. The name only, not the path. Omitted when there is no file name. |
| Dependencies, with completeness | The grouped direct graph already written for the built program. CycloneDX adds `compositions` with `aggregate` `incomplete`, because transitive dependencies are not resolved. SPDX 2.3 relationships have no completeness field. |
| Distribution licence | SPDX identifier or expression when a manifest row has one. `Commercial` and `Proprietary` stay `license.name`. A scanned file stays `NOASSERTION` in SPDX and has no CycloneDX licence. |
| SHA-512 of the deployable component | `hashes` `alg` `SHA-512` next to the existing SHA-256, and SPDX checksum algorithm `SHA512`. Written only when the file could be opened. |
| Executable property | `bsi:component:executable` = `executable` or `non-executable`. |
| Archive property | `bsi:component:archive` = `archive` or `no archive`. |
| Structured property | `bsi:component:structured` = `structured` or `unstructured`. |

Additional fields (Tables 4 and 5), written only when the value exists:

| Field | What DX.Comply writes |
|---|---|
| SBOM-URI | Not known. The CycloneDX `serialNumber` is a generated URN, not a URL you supplied. |
| Source code URI | Omitted. |
| URI of the deployable form | Omitted. |
| Other unique identifiers (CPE, purl) | Package URL when the writer already has one (`file:` for a scanned file, manifest `purl` or `pkg:delphi` for a library). CPE is omitted. |
| Original licences | The manifest stores one licence. It is written as the distribution licence. It is not copied a second time as a distinct original licence. |

Optional Table 6 fields (effective licence, source-code hash, security.txt URL) are omitted. The source-code hash algorithm is not defined by the guideline yet.

## How file properties are chosen

The executable, archive, and structured values come from the artefact type and the file extension. The file is not opened to decide them.

- Executable: artefact type application, library, package, or runtime-package, or a name ending in `.exe`, `.dll`, or `.bpl`. A source-scanned DLL is executable. A Pascal unit, a DCU, a DCP, a resource, and a MAP file are non-executable.
- Archive and structured: `.zip`, `.7z`, `.tar`, `.tgz`, `.tar.gz`, `.tar.bz2`, `.rar`, `.jar`, `.nupkg`, `.iso`, `.cab`. Everything else is `no archive` and `unstructured`. A linked binary is unstructured, which matches section 8.1.6. A self-extracting archive is not detected.

Logical components do not get a file name, a hash, or these three properties. The primary component and a manifest library are logical components. A runtime package or a missing DLL still gets the file name and the three properties, and it does not get a hash.

## Creator contact

`--sbom-creator` and `sbomCreator` accept one email address or one `http://` or `https://` URL. An empty value is ignored in the config file. On the command line an empty flag is an error. Any other text is an error: the CLI rejects it while parsing, and a bad value in `.dxcomply.json` stops generation. The supplier name and a Delphi 7 `CompanyName` are not reused as this contact.

## What is still open

- The document is CycloneDX 1.5 and SPDX 2.3, not the 1.6 and 3.0.1 minimum in TR-03183-2 version 2.1.0.
- SHA-512 is a component hash (and an SPDX checksum), not a CycloneDX 1.6 `externalReferences` entry of type `distribution`.
- CycloneDX 1.5 has no `acknowledgement` on a licence, so distribution and original licences are not marked `concluded` and `declared` that way.
- Transitive dependencies are a later change. This output marks the direct list incomplete instead of walking them.
