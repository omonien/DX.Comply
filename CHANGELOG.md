# Changelog

Released notes for shipped versions are in `docs/releases/`.

## [Unreleased]

### Added

- When a local project unit stays without a licence and was not matched by own code or by a library row, the log writes one info line. The line names `own_code_folders` for the product licence, and says that folder rules need the source path and do not match a DCU in the output folder. There is no line when every local project unit already has a licence, or is matched as own code or as a library (#207).
- The HTML and Markdown reports show the generation time on the Generated At row as `YYYY-MM-DD hh:mm:ss UTC` (for example `2026-11-20 21:11:57 UTC`). A file modification time used as a version is shown the same way. A value that is not a UTC timestamp is printed unchanged. CycloneDX JSON and XML, SPDX 2.3, and SPDX 3.0.1 keep `YYYY-MM-DDThh:mm:ssZ` (#208).
- EXE, DLL, and BPL files show the version already stored for the artefacts section in every licence list of the HTML and Markdown reports, including No licence information. The value is the numeric file version, or the file date when the file has no version resource. It stays empty when neither was stored. A third-party file does not inherit the product version. CycloneDX and SPDX output is unchanged (#203).
- Long sections of the HTML report start collapsed. The heading shows the item count, for example MIT (42 files). That covers each licence, the unit lists (Embarcadero RTL, VCL, FMX, local project, and third party), the artefact list, third-party units without a manifest, and prefix matches that were not applied. The project data, the origin summary, the structural check, and the warnings stay open. Printing or saving as PDF expands every section. The Markdown report is unchanged (#198).
- The licence overview in the HTML and Markdown reports lists the product first in its group. When the product and the project's own binary are the same file (the file name without its extension is the product name), they are one row and the version is the binary's version. A second copy of that file stays on its own row. When the names differ, the product stays first and the binary stays in the alphabetical list. A product row that is not combined with a binary shows the product version from the SBOM header, or the project version when the header has none. CycloneDX and SPDX components are unchanged (#199).
- When an output folder contains more than one executable, DX.Comply writes one info line that names them and points at the Output folders section. The SBOM is unchanged. The docs say first that each project should have its own output folder, and then show `--include=MyTool.exe` for an existing shared folder (#189).
- The command line tool builds a `.dproj`, `.dpk`, or `.groupproj` when the MAP file for the selected configuration and platform is missing. The default deep evidence mode is `when-missing`. Before that build it prints a warning that names the missing MAP file, the configuration, and the platform. `--no-build`, or `"noBuild": true` in `.dxcomply.json`, stops the run with exit code 1 and names the same MAP file, configuration, and platform. With `--ci`, the flag wins over the file. A Delphi 7 project is not compiled. A post-build event should pass the active configuration and platform (#187).
- The product, the project's own binary, and units marked as own code (`own_code_units`, `own_code_prefixes`, `own_code_folders`) take their copyright notice from `LegalCopyright` in the version resource of the built binary. A non-empty top-level `copyright` value in `.dxcomply.json` wins over that resource, including in library mode. The HTML and Markdown Copyright cells use the same notice. When both are empty, CycloneDX still omits `copyright`, SPDX 2.3 keeps `copyrightText` as `NOASSERTION`, and SPDX 3.0.1 omits `software_copyrightText`. A component manifest row keeps its own `copyright` on that library. There is no command-line flag. The IDE project options and the SBOM header dialog do not edit this key (#190).

### Fixed

- The version of a binary in the SBOM and in the HTML and Markdown reports is the numeric file version (a.b.c.d from the fixed file info). The FileVersion string, then the ProductVersion string, is used only when that fixed file info is absent. A string such as "6, 10, 5, 0" no longer replaces 6.10.5.0 (#188).
